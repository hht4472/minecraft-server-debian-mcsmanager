## 自己电脑为什么开不长

用闲置电脑跑服务端是最快的上手方式，很多服主的第一台服务器就是这么来的。但它有三个绕不开的问题。

**关机即关服。** 你睡觉、出门、重启，服务器跟着停。朋友半夜想上来盖房子，发现连不上。

**家庭宽带的延迟不适合联机。** 平时刷视频不卡，是因为视频有缓冲；游戏是实时同步，对延迟和丢包很敏感。朋友一进来就喊卡，多半是这个原因。

**没有公网 IP。** 家庭宽带通常拿不到公网地址，想让外网的朋友连进来，要么折腾内网穿透，要么进路由器做端口映射。对第一次开服的人来说，这两件事都不轻松。

云服务器把这三件事一次性解决：机房不断电、线路是为低延迟优化的、公网地址现成的。真要花的钱，一个月也就一顿饭的量级。

## 配置怎么选：先看单核，再谈内存

**单核性能比核心数重要。** Java 版服务端从 1.18 之后对单核的要求明显上去了。选机型时看 CPU-Z 单核跑分，600 分以上比较稳妥。14900K、13900K、7950X、9950X 这类高主频 CPU 都是久经验证的选择。

**内存 4 核 8G 起步。** 低于这个不是开不了，是玩家一多、模组一加，体验就打折。后期人多了，雨云的控制台里可以直接升内存，不用重装。

**区域和 IP 类型决定延迟和端口数量。** 江苏镇江是 NAT 网络，多个用户共用一个公网 IP，需要自己做端口映射，自带 15 个端口，想独享公网 IP 可以加钱选。浙江宁波的独立公网 IP 便宜，但是电信单线，高峰期其他运营商的玩家延迟会高一些。镇江和宿迁走 BGP 线路，各运营商的用户延迟都比较低，对外公开的服优先考虑这两个。

**计费模式看你玩得勤不勤。** 雨云有动态计费和固定计费两种。偶尔组局、白天基本没人的，选动态计费更划算：CPU 占用率超过 20% 才额外计费，每天还有免费额度。天天开、人常在线的，固定计费省心。

**操作系统选 Debian 12。** 后面所有命令都以它为准。

## 开服实操：Debian 12 + MCSManager

MCSManager 是一个开源免费的游戏服务器管理面板，装好之后开关服、改配置、传文件都在网页上点，不用一直对着命令行。它分两部分：Web 面板走 23333 端口，守护进程（Daemon）走 24444 端口。买的是 NAT 机型的话，这两个端口和 MC 的 25565 都要在雨云控制台的“NAT 端口映射”里做映射，协议选 TCP+UDP，外网端口用 10000–60000 之间的值。

### 第一步：确认 Java 版本

版本对不上，服务端启动直接报错退出。对照这张表装：

| 需要的 Java 版本 | Minecraft 游戏版本 |
| --- | --- |
| JDK 8 | 1.7 及以下 |
| JDK 11 | 1.8 ~ 1.16 |
| JDK 17 | 1.17 ~ 1.19 |
| JDK 21 | 1.20 及以上 |
| JDK 25 | 更新的版本分支 |

很多老教程只写“1.17 以上用 Java 17”，这条已经过时了。1.20 之后的版本要 JDK 21，装在 1.20 服上会直接跑不起来。

### 第二步：装面板

用 SSH 连上服务器，root 权限执行 MCSManager 官方一键脚本，装完浏览器打开 `http://服务器IP:23333`，按引导设置语言和管理员账号。

NAT 机型要用的不是 23333，而是你在雨云控制台给 23333 映射出来的那个外网端口。

进面板后点“节点”→“新建节点”，远程节点 IP 填服务器公网地址，端口填 24444 映射出来的外网端口，密钥填安装结束时显示的 Daemon 密钥。

### 第三步：传服务端核心，写启动命令

从 Mojang 官网或 Paper 的下载页拿到对应版本的 jar，重命名为 `server.jar`，在面板里新建实例、上传文件。实例类型选“MC Java 版服务端”，Docker 镜像选和你 Java 版本对应的那个（比如 JDK 21 就选对应 21 的镜像）。

启动命令这样写：


java -Xms1G -XX:MaxRAMPercentage=90.0 -Dfile.encoding=UTF-8 -jar server.jar nogui


每一项在干什么：

- `-Xms1G` 是 JVM 初始堆内存，启动时就预分配 1G，避免运行中频繁扩容。
- `-XX:MaxRAMPercentage=90.0` 让 JVM 最多用掉系统内存的 90%，留 10% 给系统和别的进程。它比 `-Xmx7G` 这种固定写法更省事：以后你升级内存，命令不用改。习惯写死的话，换成 `-Xmx7G` 也一样。
- `-Dfile.encoding=UTF-8` 指定编码，避免中文乱码。
- `nogui` 表示不启动图形界面。服务端在后台跑，本来也不需要窗口。注意是一个横杠，写成 `--nogui` 是错的。
- `-jar` 后面跟实际的文件名，你上传的叫什么就写什么。

如果 JDK 是 15 及以上，可以再加一个 `-XX:+UseZGC`，启用 ZGC 垃圾回收器，能减少大内存下的停顿。JDK 15 以下不支持这个参数，加了会启动失败。

### 第四步：同意 EULA

第一次启动会停下来，日志里出现 `You need to agree to the EULA in order to run the server`。这是 Mojang 的许可协议，必须手动同意。

在面板里点“服务端配置文件”，编辑 `eula.txt`，把 `eula=false` 改成 `eula=true`，保存。

### 第五步：开放端口，等 `Done`

Docker 实例还要单独把容器内的 25565 放出来：终端下方点“容器化”→“开放端口”→“新增配置”，主机端口和容器端口都填 25565，协议选 TCP。

再点开启，日志刷到出现 `Done` 就说明服务端跑起来了。

### 第六步：连进去，给自己 OP

客户端打开“多人游戏”→“添加服务器”，地址填 `公网IP:端口`，IP 和端口之间用英文冒号。NAT 机型填的是 25565 映射出去的那个外网端口，不是 25565 本身。

进服之后在面板终端输入 `op 你的游戏ID`，给自己管理员权限。

## 服务端核心怎么选

**原版（Minecraft Server）** 是 Mojang 官方发布的，没有任何修改，适合想体验原汁原味玩法的。缺点是没有优化，人多会吃力。

**Paper** 是 Spigot 的高性能分支，性能更好、优化选项多，兼容大部分 Bukkit 和 Spigot 插件。开插件服首选这个。

**Forge** 是最常用的模组加载器，装模组基本绕不开。高版本的搭建方式和其他核心不一样：先用 `-installServer` 参数跑一遍 installer，日志出现 `The server installed successfully` 之后，去文件管理里编辑 `user_jvm_args.txt` 调整内存，再把启动命令改成 `bash run.sh`。1.16.5 及以下直接运行 jar 就行。

**Fabric** 更轻量、跟进新版本更快，适合追最新版的玩家。有一个坑：Fabric 服务端必须先把 Fabric-API 放进 `mods` 文件夹，不放的话其他模组一律不生效。

**Mohist** 是 Forge + Paper 的混合结构，能同时支持 Forge 模组和 Paper 系列插件，适合既想装模组又想装插件的服。具体支持到哪个游戏版本，以官方发布页为准，这类混合核心的版本跟进一直比较慢。

## 五个最常见的坑

**一、不输入 `stop` 直接关服会回档。** 直接点面板的关闭按钮或者杀进程，服务端来不及把内存里的区块数据写回磁盘，玩家刚盖的东西就没了。关服前先在终端敲 `stop`，等进程自己退出。
